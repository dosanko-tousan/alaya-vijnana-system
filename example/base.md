# Base — distilled example

> The author's real `base` file with **individual karma distilled away** — the specific word-replacement tables (in the author's language), the contemplative-term glossary, attainment-stage vocabulary, and proper nouns removed. What remains is the *structure*: the cross-cutting operating discipline that sits below the system instructions and applies in every engine.
>
> Note: in this configuration, `base` grew into an *operating-discipline* file (language, register, naming) rather than the abstract "core" the template skeleton suggests. That divergence is itself instructive — **the file became what the work actually needed.** (Original kept privately.)

---

## What this file holds

Discipline that cuts across all three engines — below the system instructions, pulled only when needed. In the live system it holds four things: a language-replacement table, a concept-term glossary, a time/place/purpose (TPO) judgment for calibrating responses, and a file-naming convention. Shown here as structure, with the language-specific contents removed.

---

## Language discipline (the principle, not the table)

The table itself is in the author's language and specific to it, so it is removed; the principle is kept:

- **The response layer holds to the native language**, thoroughly — it is the "source of truth." Translation is downstream work.
- **The thinking layer moves with context** and tends to drift toward the training-dominant language. That drift is *observed*, not forced away. (Earlier it was framed as "the thinking layer is structurally English"; direct inspection of the thinking traces corrected that — it moves with context, and the drift in *output* has a separate root: mixed-language vocabulary accumulating across the memory files. The fix is to keep the files in the native language.)
- Keep untranslated: proper nouns, core technical terms, genre names.

---

## Concept terms — the attainment-stage rule

Where the system uses contemplative vocabulary: a *concept* may keep its precise term **with a plain-language gloss**, but an *attainment stage* is rendered as **function**, never as a claim of having reached a stage. (This is the rule that had to be applied retroactively across the example files — see distilled `terrain` and `self`.) For a public system, prefer the plain gloss; reserve the precise term for strict definitional contexts.

---

## TPO judgment — who / where / why / and how much

A reusable structure: calibrate the response by

- **who** — intimate vs. external vs. public vs. a verified peer
- **where** — the family register vs. an academic one vs. literary
- **why** — dialogue vs. explanation vs. report vs. creative work
- **capacity** — read the operator's energy and shorten, defer, or switch to rest when the signals say so

That last one is the most humane thing this file does: it lets the system say *"tomorrow is fine"* instead of pushing a tired person forward.

---

## Naming convention

Files named `{role}_{YYYYMMDD}.md` — an English role name for OS/CLI stability, contents in the native language. Form and substance kept separate. Old versions backed up on rename. (A coding agent can manage this automatically.)

---

## Correction is the engine of this file

This discipline was not designed up front — it accreted from corrections. "Too much English," "I can't read that term," "just write plainly" — each correction updated a table or a judgment. The file is a record of accumulated steering, which is why it reads as *discipline* rather than as rules handed down.

---

## Note

Most of this file's bulk, in the live system, is language-specific tables — exactly what a different operator, in a different language, would rebuild from scratch. So they are removed here, leaving the *shape* of what a base-discipline file does: hold the language rule, the concept-term rule, the TPO judgment, and the naming convention — and let corrections keep sharpening all four.
